## 0.4.0 语义问询与首项选择

普通审批和确认按完整语义接入，不依赖关键词或源卡片的布尔参数。有序选项保留原文和顺序，“同意”固定选择原始第一项，不依赖“推荐”标记。是/否问询的“拒绝”返回有效的否定答案；选项问询的“拒绝”不选择其他项；“停止”始终不作答。窗口显示按钮映射，回执返回明确的答案类型、原始选项 ID 和位置。

Skill 在发出普通询问前分流到 `request_decision`；已经显示的宿主卡片、自由文本、多选和 Codex 原生权限审批保持各自流程。5 秒行为保持不变。接口和示例见[问询映射说明](../skills/golden-finger/references/decision-mapping.md)。

## 0.3.1 稳定性与兼容改进

新增短轮询和重复等待保护、提交恢复凭据、命令预检与环境覆盖、编码修复、日志头尾与分页、MCP 进度，以及独立安装修复入口。Windows 命令行长度在提交前校验；5 秒逻辑不变，长期压测留待后续。详见[0.3.1 使用说明](ITERATION-031.md)。

## 0.3.0 执行与接入改进

本轮保持自动审批设置及计时行为不变。MCP 可在等待期间处理取消通知；“停止”取消待确认请求，运行或已获批排队的请求提供独立“终止”操作。终止不会撤销已经产生的副作用，结果保留已采集输出和原因。执行队列默认最多并行 4 条命令，同一实际 Git 工作区（无 Git 时为工作目录）串行执行；调用方填写的来源标签不是安全身份。

命令在 Windows 上先以挂起状态创建，加入 Job Object 后再恢复。响应按最终 JSON 字节预算截断日志，保证终态和退出码能够返回。终态历史和连接并发均有界。

“更多”提供通知与自动选择偏好、主动收起到托盘、脱敏摘要导出及辅助工具。关闭窗口仍按原规则退出；只有主动选择收起到托盘才隐藏窗口。摘要仅导出有限的内存历史，不记录命令、输出、令牌或来源正文。

## 当前边界

- 独立窗口是授权主体，插件没有批准接口。
- 自然语言授权通过同一次 MCP 工具调用返回当前 Codex 会话。
- 命令使用 `executable + arguments[]` 和 `shell=False`，不接受拼接好的 shell 字符串。
- 窗口展示并冻结可执行文件、直接命名的 `.ps1/.py/.pyw/.cmd/.bat/.js/.mjs/.cjs` 脚本及显式声明的参数文件 SHA-256，启动前再次核对；任一字节不一致就拒绝执行。脚本内部的 import、点调用、配置和数据文件不会递归冻结。
- Windows 上获批进程先挂起创建，加入带 `KILL_ON_JOB_CLOSE` 的 Job Object 后再恢复；执行超时、单独终止或窗口关闭会终止其进程树，但不能回滚已经发生的文件、网络或注册表副作用。
- 授权传输通道不会启动、控制或注入 Codex，也不会读写 Codex 数据库、rollout 或会话文件。窗口另有一个与授权通道隔离的生命周期协调器：它只通过正在运行的 Codex 本地只读 `list_threads` 接口显示任务状态，并把宿主提供的任务 ID 当作弱关联线索，不参与请求认领或授权。
- “安全重启 Codex”只接受窗口里的用户点击，不暴露给 MCP。只有完整任务清单新鲜、没有任何进行中 Codex/ChatGPT 任务、没有待确认或执行中授权请求时才会启用；它只发送正常关闭消息并重新打开经过路径校验的同一 Codex Desktop，不会强制结束进程。协议版本、来源完整性、管道所属进程或状态有任何疑问都会失败关闭并保持禁用。
- 不替代 Codex 原生审批、沙箱或项目规则。
- Broker 侧的请求与输出只保存在窗口进程内存中；本地端点文件仅保存端口、进程号和每次启动随机密钥。
- 一个窗口可以同时展示多个项目提交的全局请求队列，但每个项目/工具链都必须创建并认领自己的请求。`request_id` 只是可见的弱定位符；读取、等待或取消还必须持有 Broker 为该请求随机生成的 `claim_token`。
- `claim_token` 不写入端点文件、请求快照或窗口详情，窗口只显示它的 12 位 SHA-256 认领指纹用于人工对照。MCP 连接器会把令牌原样放进 `polling.next_arguments`，不得猜测、改写或转交给另一任务。
- 幂等键使用随机命名空间隔离；有稳定宿主聊天线索时，受当前用户 DPAPI 保护的最小恢复记录可跨连接器重启复用该分区。没有稳定线索时使用进程随机分区。这些线索不构成身份认证，恢复仍必须提供随机能力令牌，且仅在 Broker 保留原请求时有效。
- 每张卡片同时冻结并显示调用方提供的来源标签、项目根、任务标题，以及由连接器实例 ID 派生的 12 位非敏感指纹。这些字段帮助人在共享队列中识别串台，只是弱来源证据；真正的请求隔离仍由 `claim_token` 完成。
- 待确认有效期与命令执行上限均为 9000 秒（2 小时 30 分），可由调用方缩短。MCP 默认单次等待 30 秒，支持 0–900 秒；轮询次数不决定过期。执行超时从进程启动后独立计时，排队不消耗执行预算。
- 中继是拉取式机制：`pending/running` 时当前 Codex 回合必须逐字复用同一响应的 `polling.next_arguments`（请求 ID、认领令牌和等待时长）继续轮询到终态，中继不会主动唤醒已经结束的回合。
- MCP 连接器将消息接收与等待处理分离，Desktop 取消通知可在长等待期间处理。窗口左上方的小圆“停止”会把仍待确认的请求立即置为 `cancelled` 并唤醒该等待；它既不是同意，也不是拒绝；命令开始后按钮切换为“终止”，可单独结束该请求，但不能撤销已发生的更改。
- 中继只返回由自身窗口批准并启动的命令输出，不监听它没有启动的独立 PowerShell 或其他服务进程；这项观察边界不禁止中继自身启动经精确冻结、窗口单次批准且受超时约束的 PowerShell、Python、测试套件或测试监督器。

## 语义触发方式

Skill 按完整问题的语义选择工具，源卡片不必包含 boolean 参数，MCP 和 Broker 没有审批关键词白名单。普通是/否问询进入 `request_decision` 并返回明确的 true/false；带有序选项的问题保留原文、ID 和顺序，同意固定选择原始第一项，不依赖推荐标记。偏好、设计选择和信息确认只要确实需要用户给出是/否或单选答案，也适用此流程。

单次具体动作授权使用 `request_consent`；窗口执行精确命令使用 `request_command_execution`。问询分流发生在普通宿主卡片创建前，不能追溯接管已经弹出的卡片。自由文本、多选、原生权限审批、本插件自身安装维护和作用域选择仍走各自流程。详见[问询映射](../skills/golden-finger/references/decision-mapping.md)。

## 使用作用域与窗口生命周期

插件运行时与引用作用域是两层：`golden-finger` 应安装并启用于用户级 personal/global Codex 插件环境，使 Skill 和 MCP 在任何项目中都可被发现；`C:\finger` 这样的仓库目录只是开发源码，项目中的 `AGENTS.md` 也不会安装或复制插件。项目/全局标记只决定已全局可用的金手指何时被引用。

首次采用金手指时，Codex 必须先在普通对话中让用户约定引用范围：`仅本次`、`当前任务（推荐）`、`当前项目 <绝对根目录>`、`所有项目`，或暂不使用。作用域只是未来遇到合格请求时的路由偏好，不是长期授权；每一个动作仍需要一张被冻结的请求卡，由窗口手动或按自动审批设置决定；若另有规则要求用户明确确认，自动回执不能替代点击。若用户没有明确选择，不得擅自扩大范围。

`仅本次` 和 `当前任务` 只保留在当前任务语境中。`当前项目` 与 `所有项目` 分别在项目根或 Codex 用户目录的有效指令文件中持久化一小段带标记的作用域规则：该层已有 `AGENTS.override.md` 时写入它，否则使用 `AGENTS.md`，避免规则被 override 静默屏蔽。不复制整份 Skill；取消持久作用域时也只移除同一文件中的标记块。Broker 不保存作用域，因为它不能认证 Codex 的任务或项目身份，作用域也不会进入请求哈希、认领令牌或批准回执。

每个新请求提交前都先调用 `relay_health`。当窗口未运行、正在关闭或连接中断时，健康结果会失败关闭并给出两个结构化选择：`启动金手指窗口并继续作用域`，或 `取消金手指作用域`。Codex 不会自动启动独立授权窗口；它应引导用户双击桌面/开始菜单快捷方式，没有快捷方式时打开插件目录的 `scripts\launch_relay.pyw`，开发态则可在普通权限终端运行 `python scripts\relay_broker.py`。用户报告已打开后仍须重新检查健康状态。

中继和 MCP 都是拉取式的，不能在 Codex 回合结束后后台监测或主动唤醒。只有活跃回合里的健康检查、提交或轮询才能发现失联；仅当结果带有 `reason_code=relay_window_closed` 时才称为“窗口已关闭”，普通连接错误只称“窗口不可用”。重启窗口不会恢复旧的内存请求；取消作用域也不等于批准或拒绝当前动作，更不能撤销已经批准或运行中的命令。

## 一键启动

自 0.1.2 起提供用户主动触发、无控制台窗口的入口：

    scripts\launch_relay.pyw

源码/开发安装的桌面或开始菜单快捷方式应以当前用户的 `pythonw.exe` 为目标，以稳定源码目录的 `launch_relay.pyw` 为参数，并把工作目录设为该脚本所在的 `scripts` 目录。自包含发行包则直接指向稳定安装目录的 `bin\GoldenFinger.exe`，不要求 Python 或 PATH。两者都不得指向会随每次更新变化的 Codex 版本化缓存目录。

启动器不会自动启动、不会注册开机启动、不会请求管理员权限，也不会由 Codex 或 MCP 连接器调用。用户双击后，中继窗口可连续服务多个请求和 Codex 会话；只有窗口已关闭、异常退出或 Windows 重启后才需要再次双击。若启动失败或已有一个实例，错误会显示在对话框中，而不是消失在无控制台进程里。

创建桌面快捷方式属于一次单独的客户端变更，不由插件安装过程静默执行。

## 外观与新请求提醒

窗口优先读取 `~/.codex/config.toml` 的 `[desktop].appearanceTheme`，并兼容旧的根级字段；支持 `light`、`dark` 和 `system`。当值为 `system` 或配置不可读时，窗口跟随 Windows 应用主题；它不会注入或控制 Codex 进程。浅色、深色背景与强调色采用 Codex 外观设置公开的基线。在支持 Windows 亚克力背景的系统上，窗口背景保持 60% 不透明、文字保持 100% 不透明；透明客户区后方同时放置一个几乎不可见但 Alpha 非零的命中保护层，所以点击玻璃留白不会穿透到 Codex 或其他底层窗口。保护层若无法建立，界面会失败关闭透明客户区并退回不透明背景。窗口同时请求系统圆角和匹配的标题栏。当前 Windows `ACCENT_POLICY` 路径只提供背景着色 Alpha，不提供可调模糊半径；实际模糊范围由系统合成器决定。

窗口可调整尺寸，初始为 `980 × 720`，`920 × 600` 是舒适布局基线，同时允许 Windows Snap 缩到 `640 × 600`；若系统字体或 DPI 需要更大空间，运行时会继续上调高度。主体是“左右两条主操作通道 + 按需第三层”的渐进式三列：左侧合并显示 Codex 任务与中继请求，中间保留授权决定，详细参数默认收起，打开后在两列上方形成可滚动覆盖层，不再把窗口强行撑到屏幕外。宽度低于 820px 时会压缩任务列、隐藏可推导的等待策略文字，并把安全重启按钮移到独占行。居中的大圆形“同意本次”与两个小圆形“停止”“拒绝”会随可用空间重新计算位置和直径，最小命中尺寸和列表行高均为 40px；三者同时是原生 Windows Button，可向 UI Automation/Narrator 暴露名称、焦点、启用状态和 Invoke。筛选使用互斥单选状态，空清单、筛选无结果、任务清单不可用和本地中继状态分别显示。权限横幅已移除；主界面副标题与命令详情均明确显示普通用户或管理员权限，管理员模式还会注明获批命令继承该权限。

每次检测到新请求只提醒一次：列表按最新优先重排，默认自动选中最新项并滚入视野；正在查看详情时保留当前选择。默认唤起最小化窗口，并在仍有待确认请求期间保持置顶；这些行为可在“更多 → 通知与选择偏好”分别调整，提示音独立生效。新请求只触发一次 Windows 前台激活尝试，键盘焦点落在非操作性的请求列表，不会把 Enter 或空格预设为批准；250 ms 刷新也不会再清除正在按下的按钮状态。最后一个待确认请求处理后会自动取消置顶。

空闲、筛选无结果和只读任务状态也保留三颗圆形按钮，但全部禁用并清除授权请求选择；选中待确认的冻结请求时启用决定按钮；选中已获批排队或运行的请求时，只启用“终止”操作。主按钮与两颗辅助按钮共用水平中心线，按钮区保留至少 168px 高度，避免长文字把圆形控件挤成小点。外部留白与卡片内边距统一为 16px，分组间隔采用 4 / 8 / 12 / 16px 节奏；顶部工具保持至少 40px 命中高度。摘要按实际栏宽和系统字体测量换行，动作与风险最多显示两行，窄窗目标显示一行，省略时“详细参数”会标注“含省略”；冻结的完整动作、目标、风险与恢复路径不会裁剪，仍可在详情覆盖层核对。长内容或字体缩放需要额外高度时，窗口会提高安全高度下限。空列表提示独立于真实任务行，收到任务或请求后自动移除。

“新请求提示音”默认开启，可在窗口右上角随时关闭或重新开启。选择只保存到中继自己的 `ui-settings.json`，不会修改 Codex 或 Windows 设置；重复轮询同一请求不会再次发声。

右上角“接入检查”（原“诊断”）会打开可滚动、可复制的只读安装快照：Broker/连接器版本与精确 build ID、协议号、源码或自包含运行模式、权限、Job Object 能力、插件启用状态、版本化缓存、快捷方式及最近连接器指纹。快照明确脱敏，不包含端点 bearer secret、`claim_token`、原始连接器实例 ID、请求正文或命令输出。它不调用或控制 Codex，也不会自动修复、安装或切换版本。

“更多”中的“编辑 Computer Use 指南”会用 Windows 为 `.md` 文件配置的默认软件打开插件的 `docs/guidance.md`。每次点击都重新定位：优先使用 `CODEX_HOME`，未设置时使用当前用户的 `~/.codex`；优先匹配当前本地 `openai-bundled` 插件清单中的版本，清单不可用时按数值版本号选择缓存中实际包含指南的最新版本，不写死用户名或版本号。未安装插件、找不到文件或默认软件无法打开时会给出错误与处理建议。该按钮不修改指南内容；插件升级可能覆盖用户对缓存文件的编辑。

## 轮询与执行设置

等待策略保留由 `900 秒 × 10 次` 派生的 `9000 秒`（2 小时 30 分）待确认总预算和执行上限。MCP 默认单次等待 30 秒，允许 0–900 秒；0 为立即读取。调用次数仅供观察，重复或并发等待不会消耗有效期限。旧版轮询设置继续忽略，提示音和独立自动审批参数保持原行为。

顶部提供“自动审批等待”输入和“应用”按钮，接受 `0–3600` 整数秒，默认 `5`，`0` 表示关闭。每个 `pending` 请求从窗口首次发现它开始独立计时，选择另一个请求不会重置计时；到时仍是 `pending` 才会同意，命令请求将直接进入执行。界面显示最近到期请求的倒计时，并明确提示命令会到时执行。该参数不是 MCP 的 900 秒轮询等待，也不改变请求有效期或执行上限。

点击同意、拒绝或停止后，该请求不会再被自动处理；取消、过期或关窗也不会触发自动同意。编辑参数但未应用时暂停自动审批，点击“应用”后为所有仍待处理的请求重新开始完整等待。查看带抓取的详情层、按住决定按钮、关闭确认框期间暂停并清空旧计时，结束后重新计时。损坏或不可读的偏好文件会关闭自动审批。自动回执包含 `approval_mode=automatic` 和等待秒数，不含 `human_action`；手动点击回执为 `approval_mode=manual`，保留 `human_action=approved_once`。自动回执不能替代其他规则要求的明确人工批准，也不能绕过 Codex 原生审批。

每个请求都会冻结并哈希有效期限和执行上限。活动响应给出下一次精确参数、等待统计和剩余时间。只有单调有效期限到达时，待确认请求才进入 `expired`；命令运行后使用独立执行超时。短轮询保持原请求及 claim，不自动重提交动作。

语义问询与结构化答案使用本地协议版本 8。端点读取和每次认证请求都会同时比对包版本与运行时 build ID；只要窗口、MCP 连接器或缓存来自不同构建就失败关闭。发布安装时窗口运行时和 Codex 客户端插件必须配套升级。

## 开发态启动

安装插件前，用户需要在普通权限终端中手动启动窗口：

    python scripts\relay_broker.py

构建脚本不会顺带安装、启动窗口或修改 Codex 配置。Agent 可以在用户已授予的安装范围内下载、校验、安装并完成受支持配置；创建快捷方式、打开窗口或首次联调也应遵循相应的用户授权。

## 换电脑继续开发

在新的 Windows 电脑上安装 Git 和 Python 3.13，然后在自己控制的普通权限 PowerShell 中执行：

```powershell
git clone https://github.com/LeoSasion/golden-finger-for-codex.git
cd golden-finger-for-codex
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -X utf8 scripts\static_validate.py
```

后续构建也使用同一个虚拟环境解释器，避免依赖安装到另一套 Python：

```powershell
.\.venv\Scripts\python.exe scripts\build_windows_release.py
.\.venv\Scripts\python.exe scripts\verify_windows_release.py dist\golden-finger-0.4.0
```

Git 保存源码、测试、Skill、构建脚本和开发文档；`build/`、`dist/`、虚拟环境、UI 偏好和本机诊断截图不入库，发行包可在新电脑重新生成。不要迁移旧电脑的端点密钥、请求令牌或正在等待的请求。

Codex 插件安装/启用及桌面快捷方式需要在新电脑单独配置，不会随克隆自动执行。窗口与 MCP 连接器必须使用同一完整发行包、相同 build ID；不要只复制 EXE，也不要混用旧缓存的连接器。

## 自包含 Windows 发行包

`requirements-build.txt` 固定构建环境及界面依赖。下面的构建会在 `build/` 中盖入同一 `rel-…` build ID，用 PyInstaller 的共享 `COLLECT` onedir 生成无控制台窗口 `GoldenFinger.exe` 和控制台 MCP 连接器 `golden-finger-mcp.exe`，并让二者共用同级 `golden-finger.runtime` 目录，再把插件、SHA-256 清单和 `BUILD-ID.txt` 打包到 `dist/`；窗口与 MCP 两个 EXE 的既有 `bin\...` 路径不变。它不会安装插件、修改 Codex 配置或创建快捷方式。

    python -m pip install -r requirements-build.txt
    python scripts\build_windows_release.py
    python scripts\verify_windows_release.py dist\golden-finger-0.4.0

发行包还包含 `GoldenFingerSetup.exe` 本地安装管理工具。验证器逐文件复算清单、检查头图相对引用完整性，检查共享 onedir runtime 目录，实际启动 MCP EXE 完成 `initialize`，并让窗口 EXE 用 `--self-test-output` 在不打开 GUI 的情况下验证版本、build ID、自包含模式和 Windows Job Object。运行、复制或安装时必须保留完整发行包，不能只取两个 EXE。GitHub Actions 的 Windows runner 会从干净检出重复单元测试、静态校验、构建和验证；本地成功不替代真实干净 Windows 机器的首次启动与交互验收。

安装器管理从 0.3.0 的完整清单格式开始，不会自动接管旧 0.2.0 缓存。固定目录中的窗口和连接器启动器跟随 `active.json` 切换版本；Codex 导入或复制的插件缓存仍需通过客户端支持的方式重新导入、启用和连接。升级及回退都不会自动重放旧请求。具体命令与恢复步骤见[本机安装指南](LOCAL-GUIDE.md)。

## 使用方式

1. 首次采用时，用户在普通对话中选择金手指的路由作用域。
2. Codex 调用 `relay_health`；若窗口不可用，用户选择启动并保留作用域，或取消作用域。
3. 窗口健康后，Codex 调用 `request_decision`、`request_consent` 或 `request_command_execution`，同时提交真实的来源标签、项目根和任务标题；Broker 返回请求 ID 与仅当前工具链持有的认领令牌。
4. 用户核对来源项目/任务/连接器指纹、动作、目标、风险、恢复路径、命令、脚本摘要、请求哈希和认领指纹。
5. 用户点击“同意本次”或“拒绝”；若只想结束等待而不表达两者，点击“停止”。自动审批开启时，倒计时结束仍待处理的请求会自动同意；需要逐笔人工确认时先把自动审批等待设为 0 并应用。
6. MCP 工具把结构化结果返回当前 Codex 工具调用；若仍为 `pending/running`，Codex 在当前回合按返回的精确参数重复等待已认领请求，直到完成、拒绝、失败或过期，再据此继续或停止。

## 版本状态

0.2.0 把跨项目隔离从“知道请求 ID 即可读取”升级为每请求能力式认领：请求 ID 只负责定位，随机 `claim_token` 才允许读取、等待或取消；连接实例随机 ID 同时隔离幂等键命名空间。窗口新增项目/任务/来源标签与连接器指纹供人工辨认，但明确保持弱绑定。端点和认证请求严格比对组件版本与 build ID；命令冻结可执行文件及直接脚本参数，启动前复验，并在 Windows Job Object 中约束进程树。窗口采用默认收起详情的三列极简布局，并增加只读任务清单与失败关闭的安全重启门禁；任务标题只作不受信任的显示文本，重启能力不进入授权传输。窗口同时提供脱敏安装诊断和明确的关窗后果，自包含 Windows 构建产出 Broker/MCP EXE、哈希清单与干净 Windows CI 验证。该历史版本把等待固定为 `900 × 10`，并增加不会表达同意或拒绝、可立即唤醒等待的窗口“停止”操作；MCP 的 `notifications/cancelled` 仍是同步连接器上的尽力取消。Skill 仍按单次授权意图匹配，首次采用时协商路由作用域，窗口失联时提供启动或取消作用域。本版请求前缀为 `gfr_`，本地协议为 5，因此窗口运行时与客户端插件必须来自同一构建。

0.1.9 将窗口改为极简响应式布局：加入 DPI 感知的 `920 × 600` 基线最小尺寸，固定底部操作栏和右下角“同意本次”，把等待策略收敛为实时乘法公式，并移除重复的权限横幅。命令详情继续明确显示执行权限及管理员继承影响；授权、轮询、透明防穿透和本地协议边界不变。

0.1.8 将品牌统一为“Codex金手指 / Golden Finger for Codex”，同时保留“人机授权中继”和“Yes工程师”作为功能与搜索关键词。内部插件 ID、Skill ID 与源码目录统一为 `golden-finger`，MCP 配置键使用 `golden_finger`；这是需要重新发布和安装的不兼容标识迁移，本地协议版本仍保持 2。

0.1.7 为玻璃客户区加入非零 Alpha 命中保护层，杜绝点击穿透；同时把等待设置重排为两个输入和一个实时派生结果，取消保存按钮，将单次轮询下限提高到 10 秒，并让命令执行上限自动等于轮询秒数与轮询次数的乘积。它继续保持背景 60%、文字 100%，允许 `request_consent` 为后续 Codex 管理操作收集一次性自然语言授权，并禁止中继器直接启动或控制 Codex。它仍是源码原型，不是普通用户发行包。后续发行目标是单文件 Windows 窗口程序，不要求管理员权限、Python、PATH 或手动依赖安装。
