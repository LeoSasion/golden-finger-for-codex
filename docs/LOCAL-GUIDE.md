# 本机安装、接入与故障恢复

## 首次运行

从项目 GitHub Releases 获取完整 Windows x64 ZIP，解压后运行 `bin\GoldenFinger.exe`。保留 `golden-finger.runtime` 和配套 MCP EXE。主界面会显示普通用户或管理员权限；执行命令继承窗口权限。

本轮没有更改自动审批计时、策略、默认值或配置迁移。需要了解既有审批方式时，请查看 README 的“轮询与执行设置”。

## 稳定安装目录

发行包附带 `bin\GoldenFingerSetup.exe`，无需另装 Python。以下命令从解压后的包目录执行；选择自己拥有写入权限的固定目录：

```powershell
.\bin\GoldenFingerSetup.exe install . --root "$env:LOCALAPPDATA\GoldenFingerApp"
.\bin\GoldenFingerSetup.exe status --root "$env:LOCALAPPDATA\GoldenFingerApp"
```

安装器在固定目录内保存完整版本和 `active.json`，生成稳定启动入口。它不会配置开机启动、创建桌面快捷方式、修改 Codex 配置或自动启动程序。

- `GoldenFinger.cmd`：启动当前版本窗口。
- `golden-finger-mcp.cmd`：启动当前版本连接器，供支持命令式 MCP 配置的客户端使用。
- `GoldenFingerSetup.cmd`：管理当前安装。

这些入口依赖 Windows PowerShell，不要求 Python；组织策略禁止执行脚本时，可使用 `status` 返回的完整 EXE 路径，遵守本机策略，不绕过系统限制。

不要从未知来源安装。ZIP 的 `--sha256` 必须使用可信发布页面提供的摘要；包内清单用于检查完整性，本身不证明发布者身份。

## 接入 Codex

1. 在 Codex 支持的插件安装入口导入 `status` 显示的 `plugin_directory` 完整目录。
2. 如果客户端没有本地目录导入入口，按该客户端支持的插件市场流程安装；不要编辑 Codex 私有数据库或伪造缓存安装。
3. 打开金手指窗口的“接入检查”。未发现缓存不等于 EXE 故障，尚未读到启用状态不等于已禁用。
4. 在要使用的聊天中调用 `relay_health`。窗口与连接器必须匹配版本和 build ID。
5. 提交一条仅返回文字的请求，确认该聊天收到终态结果。旧连接记录或任务线索不能证明新的聊天已经接入。

如需复制完整活动插件到另一个导入目录：

```powershell
.\bin\GoldenFingerSetup.exe export D:\Plugins\GoldenFinger --root "$env:LOCALAPPDATA\GoldenFingerApp"
```

导出目标必须不存在，避免覆盖现有插件内容。导出后仍需通过客户端支持的方式安装和启用。

## 更新与回退

更新前结束或明确终止正在运行的请求，正常关闭窗口及旧 MCP 连接器。安装器遇到安装根内的运行中 EXE 会拒绝切换版本。

```powershell
.\bin\GoldenFingerSetup.exe install D:\Downloads\golden-finger-0.3.1-windows-x64.zip --root "$env:LOCALAPPDATA\GoldenFingerApp"
.\bin\GoldenFingerSetup.exe rollback --root "$env:LOCALAPPDATA\GoldenFingerApp"
```

更新会先校验并复制到新版本目录，再切换活动指针；保留上一个版本供回退。回退也会校验目标版本。失败时不要手动拼装不同版本的 EXE 和 runtime。

若 Codex 导入的是具体版本目录或复制的缓存，升级/回退后需要按客户端支持的方式重新导入或更新插件，并重新连接 MCP。稳定启动入口不会修改客户端已经启动的连接器。窗口内存请求不跨重启恢复，也不会自动重放命令。

## 等待、执行与终止

- **待确认 → 停止**：取消等待，既不批准也不拒绝。
- **已获批排队 → 终止**：移出执行队列，命令不会启动。
- **正在执行 → 终止**：结束该请求的进程树，保留已经采集的输出；不会撤销已发生的更改。
- **Codex 停止当前调用**：取消通知及时处理；如果命令已经开始，不把停止等待解释成终止执行。需要明确调用 `terminate_command` 或点击窗口“终止”。

最多并发执行 4 条命令；同一实际 Git 工作区的子目录串行，非仓库目录按实际工作目录串行。来源标签仅用于显示，不作为身份认证。排队时显示排队状态，执行超时从实际执行阶段计算。

输出会标记采集截断或传输截断；看到截断标记不能把当前片段当作完整日志。进程结果和退出码优先返回。

## 通知、托盘与摘要

“更多 → 通知与选择偏好”可以选择是否唤起、置顶、自动选中新请求。偏好保存在独立的 `window-preferences.json`，不会改变审批设置。

“收起到系统托盘”只在托盘图标成功创建后隐藏窗口。托盘菜单可重新打开或退出；退出仍受当前活动请求的关闭确认保护。窗口的关闭按钮保持退出语义，不会悄悄改为托盘常驻。

“导出脱敏操作摘要”仅在用户选定文件时落盘；包括请求指纹、时间、审批方式、执行阶段和结果代码。不会写入原始命令、输出、令牌、任务标题或项目路径。摘要仅覆盖当前窗口内仍保留的有限历史，不是永久审计系统。

## 故障定位

| 现象 | 检查与处理 |
|---|---|
| 窗口正常，聊天找不到工具 | 检查插件安装/启用和当前聊天工具注册，不要仅重开窗口 |
| 构建不匹配 | 窗口与 MCP 换成同一完整发行包，关闭旧连接后重新连接 |
| 启用状态尚未确认 | 可能没有可识别配置、配置冲突或读取失败；以客户端插件设置为准 |
| 命令长时间排队 | 同工作区已有运行命令，或全局执行槽已满；可终止对应排队项 |
| Job Object 检测失败 | 查看检测错误码；此时不要承诺进程树约束已可用 |
| 更新提示正在运行 | 正常关闭对应窗口和连接器，再重试；安装器不会强杀进程 |
| 已执行但输出不全 | 检查 `stdout_truncated` / `stderr_truncated` 等标记 |
| 关闭窗口后旧请求消失 | 请求只在内存中，不恢复、不重放；核对实际副作用后决定下一步 |

## 验收清单

自动回归覆盖：长等待取消、取消与提交竞态、单请求终止、挂起启动与 Job 绑定、同项目排队、大中文双路输出、配置诊断、版本安装/升级/回退、恶意 ZIP 路径、完整头图资产及 EXE 自检。

发行构建采用固定 Python 版本，CI 单测覆盖 3.13 和 3.14。以下环境需要在对应机器手工验收，不能由本机测试代替：Windows 10/11 干净安装、多显示器、100%/150%/200% DPI、屏幕阅读器、受限组织策略、托盘重启恢复。

0.3.1 的短等待、恢复、环境预检、输出分页与损坏修复见 [迭代指南](ITERATION-031.md)。长期运行验证按用户要求后续安排。
