# Codex金手指

英文名：Golden Finger for Codex。

Codex金手指是为“Yes工程师”准备的人机授权中继：它把单次授权请求交给独立窗口，完整展示被冻结的动作，只有用户点击“同意本次”才返回同意，或执行精确的本地程序与参数。

## 当前边界

- 独立窗口是授权主体，插件没有批准接口。
- 自然语言授权通过同一次 MCP 工具调用返回当前 Codex 会话。
- 命令使用 \`executable + arguments[]\` 和 \`shell=False\`，不接受拼接好的 shell 字符串。
- 窗口展示并冻结可执行文件 SHA-256，启动前再次核对；不一致就拒绝执行。
- 不启动、不控制、不注入 Codex；不读写 Codex 数据库、任务或 rollout。
- 不替代 Codex 原生审批、沙箱或项目规则。
- 请求与输出只保存在窗口进程内存中；本地端点文件仅保存端口、进程号和每次启动随机密钥。
- 窗口只让用户设置新请求的单次轮询与等待确认次数；等待总预算和命令执行上限都由这两个数相乘自动得到。出厂值为 `50 × 72 = 3600` 秒。
- 中继是拉取式机制：\`pending/running\` 时当前 Codex 回合必须用同一请求 ID 继续轮询到终态，中继不会主动唤醒已经结束的回合。
- 中继只返回由自身窗口批准并启动的命令输出，不监听它没有启动的独立 PowerShell 或其他服务进程；这项观察边界不禁止中继自身启动经精确冻结、人工单次批准且受超时约束的 PowerShell、Python、测试套件或测试监督器。

## 一键启动

自 0.1.2 起提供用户主动触发、无控制台窗口的入口：

    scripts\launch_relay.pyw

桌面或开始菜单快捷方式应以当前用户的 `pythonw.exe` 为目标，以个人市场中稳定插件源的 `launch_relay.pyw` 为参数，并把工作目录设为该脚本所在的 `scripts` 目录。快捷方式不得指向会随每次更新变化的 Codex 版本化缓存目录。

启动器不会自动启动、不会注册开机启动、不会请求管理员权限，也不会由 Codex 或 MCP 连接器调用。用户双击后，中继窗口可连续服务多个请求和 Codex 会话；只有窗口已关闭、异常退出或 Windows 重启后才需要再次双击。若启动失败或已有一个实例，错误会显示在对话框中，而不是消失在无控制台进程里。

创建桌面快捷方式属于一次单独的客户端变更，不由插件安装过程静默执行。

## 外观与新请求提醒

窗口优先读取 `~/.codex/config.toml` 的 `[desktop].appearanceTheme`，并兼容旧的根级字段；支持 `light`、`dark` 和 `system`。当值为 `system` 或配置不可读时，窗口跟随 Windows 应用主题；它不会注入或控制 Codex 进程。浅色、深色背景与强调色采用 Codex 外观设置公开的基线。在支持 Windows 亚克力背景的系统上，窗口背景保持 60% 不透明、文字保持 100% 不透明；透明客户区后方同时放置一个几乎不可见但 Alpha 非零的命中保护层，所以点击玻璃留白不会穿透到 Codex 或其他底层窗口。保护层若无法建立，界面会失败关闭透明客户区并退回不透明背景。窗口同时请求系统圆角和匹配的标题栏。当前 Windows `ACCENT_POLICY` 路径只提供背景着色 Alpha，不提供可调模糊半径；实际模糊范围由系统合成器决定。

窗口可调整尺寸，初始为 `1120 × 720`，基线最小尺寸为 `920 × 600`；若系统字体或 DPI 需要更大空间，运行时会继续上调最小值。顶部信息、中央分栏和底部操作栏采用独立网格行，只有中央分栏参与伸缩，因此“同意本次”始终保留在右下角。权限横幅已移除；命令请求的详情仍明确显示普通用户或管理员权限，管理员模式还会注明获批命令继承该权限。

每次检测到新请求只提醒一次：列表自动按最新优先重排、自动选中最新项并滚入视野；若窗口已最小化则恢复，并在仍有待确认请求期间保持置顶。新请求只触发一次 Windows 前台激活尝试，键盘焦点落在非操作性的请求列表，不会把 Enter 或空格预设为批准；250 ms 刷新也不会再清除正在按下的按钮状态。最后一个待确认请求处理后会自动取消置顶。

“新请求提示音”默认开启，可在窗口右上角随时关闭或重新开启。选择只保存到中继自己的 `ui-settings.json`，不会修改 Codex 或 Windows 设置；重复轮询同一请求不会再次发声。

## 轮询与执行设置

窗口中的等待策略压成一条极简公式：`轮询 [50] 秒 × 上限 [72] 次 = 总上限 3600 秒 · 1 小时`，下一行只保留简短的自动应用状态或输入错误。可配置的有界范围为：单次轮询 10–50 秒、等待确认最多 1–720 次，且相乘后的总预算必须为 10–36000 秒。命令执行上限自动与该总预算同步，不再维护第三套手工数值。

两个输入一有有效改动，界面就立即重算总预算，并在 250 ms 防抖后自动应用和保存；没有“保存设置”按钮。配置仍只应用到随后创建的新请求。每个请求都会冻结并哈希当时的策略版本、单次等待、轮询上限和派生的命令超时；已存在请求不会被中途改写。Codex 的每个活动响应都会收到下一次精确参数、已用次数和剩余次数，不保存或猜测另一套值。正数等待只在请求仍为 `pending` 时消耗次数；次数或时间预算用尽仍无人决定时，请求进入 `expired`。命令进入 `running` 后改由已经冻结的派生执行超时负责，不能因为确认阶段的计数用完而被静默遗留或终止。

这组同步字段继续使用本地协议版本 2；发布安装时窗口运行时和 Codex 客户端插件必须配套升级，版本不一致会失败关闭。新版加载后，日后只在窗口内调整有效数值不需要重启 Codex。

## 开发态启动

安装插件前，用户需要在普通权限终端中手动启动窗口：

    python scripts\relay_broker.py

本仓库没有自动安装、自动启动或 Codex 配置修改。插件安装、创建快捷方式和首次实际联调是彼此独立的授权步骤。

## 使用方式

1. 用户启动“Codex金手指”窗口。
2. Codex 调用 \`request_consent\` 或 \`request_command_execution\`。
3. 用户核对动作、目标、风险、恢复路径、命令和请求哈希。
4. 用户点击“同意本次”或“拒绝”。
5. MCP 工具把结构化结果返回当前 Codex 工具调用；若仍为 \`pending/running\`，Codex 在当前回合重复等待同一请求，直到完成、拒绝、失败或过期，再据此继续或停止。

## 开发验证

在 Codex 内只做无副作用的语法、清单和 Skill 静态验证。涉及启动窗口、执行命令或实际连接 Codex 的测试，应在外部终端中按单独授权进行。

静态验证入口：

    python scripts\static_validate.py

外部单元测试入口：

    python -m unittest discover -s tests -v

外部窗口联调步骤见 [EXTERNAL-TESTING.md](EXTERNAL-TESTING.md)。附带的 \`manual_smoke_client.py\` 只有固定“同意”与固定打印两种场景，不提供任意命令入口，也没有批准接口。

## 版本状态

0.1.9 将窗口改为极简响应式布局：加入 DPI 感知的 `920 × 600` 基线最小尺寸，固定底部操作栏和右下角“同意本次”，把等待策略收敛为实时乘法公式，并移除重复的权限横幅。命令详情继续明确显示执行权限及管理员继承影响；授权、轮询、透明防穿透和本地协议边界不变。

0.1.8 将品牌统一为“Codex金手指 / Golden Finger for Codex”，同时保留“人机授权中继”和“Yes工程师”作为功能与搜索关键词。内部插件 ID、Skill ID 与源码目录统一为 `golden-finger`，MCP 配置键使用 `golden_finger`；这是需要重新发布和安装的不兼容标识迁移，本地协议版本仍保持 2。

0.1.7 为玻璃客户区加入非零 Alpha 命中保护层，杜绝点击穿透；同时把等待设置重排为两个输入和一个实时派生结果，取消保存按钮，将单次轮询下限提高到 10 秒，并让命令执行上限自动等于轮询秒数与轮询次数的乘积。它继续保持背景 60%、文字 100%，允许 `request_consent` 为后续 Codex 管理操作收集一次性自然语言授权，并禁止中继器直接启动或控制 Codex。它仍是源码原型，不是普通用户发行包。后续发行目标是单文件 Windows 窗口程序，不要求管理员权限、Python、PATH 或手动依赖安装。
