# Codex金手指

英文名：Golden Finger for Codex。

Codex金手指是为“Yes工程师”准备的人机授权中继：它把单次授权请求交给独立窗口，完整展示被冻结的动作，只有用户点击“同意本次”才返回同意，或执行精确的本地程序与参数。

## 当前边界

- 独立窗口是授权主体，插件没有批准接口。
- 自然语言授权通过同一次 MCP 工具调用返回当前 Codex 会话。
- 命令使用 \`executable + arguments[]\` 和 \`shell=False\`，不接受拼接好的 shell 字符串。
- 窗口展示并冻结可执行文件以及参数数组中直接命名的 `.ps1/.py/.pyw/.cmd/.bat` 脚本 SHA-256，启动前再次核对；任一字节不一致就拒绝执行。脚本内部的 import、点调用、配置和数据文件不会递归冻结。
- Windows 上获批进程会立即加入带 `KILL_ON_JOB_CLOSE` 的 Job Object；执行超时或窗口关闭会终止其进程树，但不能回滚已经发生的文件、网络或注册表副作用。
- 授权传输通道不会启动、控制或注入 Codex，也不会读写 Codex 数据库、rollout 或会话文件。窗口另有一个与授权通道隔离的生命周期协调器：它只通过正在运行的 Codex 本地只读 `list_threads` 接口显示任务状态，并把宿主提供的任务 ID 当作弱关联线索，不参与请求认领或授权。
- “安全重启 Codex”只接受窗口里的用户点击，不暴露给 MCP。只有完整任务清单新鲜、没有任何进行中 Codex/ChatGPT 任务、没有待确认或执行中授权请求时才会启用；它只发送正常关闭消息并重新打开经过路径校验的同一 Codex Desktop，不会强制结束进程。协议版本、来源完整性、管道所属进程或状态有任何疑问都会失败关闭并保持禁用。
- 不替代 Codex 原生审批、沙箱或项目规则。
- Broker 侧的请求与输出只保存在窗口进程内存中；本地端点文件仅保存端口、进程号和每次启动随机密钥。
- 一个窗口可以同时展示多个项目提交的全局请求队列，但每个项目/工具链都必须创建并认领自己的请求。`request_id` 只是可见的弱定位符；读取、等待或取消还必须持有 Broker 为该请求随机生成的 `claim_token`。
- `claim_token` 不写入端点文件、请求快照或窗口详情，窗口只显示它的 12 位 SHA-256 认领指纹用于人工对照。MCP 连接器会把令牌原样放进 `polling.next_arguments`，不得猜测、改写或转交给另一任务。
- 每个 MCP 连接器进程另有一个内存随机实例 ID，只用于隔离幂等键命名空间，不冒充 Codex 项目或任务身份。在 Broker 仍运行且请求仍保留时，认领令牌本身跨连接器重启仍有效。
- 每张卡片同时冻结并显示调用方提供的来源标签、项目根、任务标题，以及由连接器实例 ID 派生的 12 位非敏感指纹。这些字段帮助人在共享队列中识别串台，只是弱来源证据；真正的请求隔离仍由 `claim_token` 完成。
- 等待策略固定为 `900 秒 × 10 次 = 9000 秒`（2 小时 30 分）；窗口不再提供一套容易与 Codex 漂移的可变轮询设置。等待总预算和命令执行上限都冻结为同一策略。
- 中继是拉取式机制：\`pending/running\` 时当前 Codex 回合必须逐字复用同一响应的 `polling.next_arguments`（请求 ID、认领令牌和等待时长）继续轮询到终态，中继不会主动唤醒已经结束的回合。
- MCP 连接器仍同步读取 Desktop 的取消通知，因此 Desktop“停止”在一次 900 秒等待期间可能延迟。窗口左上方的小圆“停止”会把仍待确认的请求立即置为 `cancelled` 并唤醒该等待；它既不是同意，也不是拒绝，且不能撤销已经批准或执行中的命令。
- 中继只返回由自身窗口批准并启动的命令输出，不监听它没有启动的独立 PowerShell 或其他服务进程；这项观察边界不禁止中继自身启动经精确冻结、人工单次批准且受超时约束的 PowerShell、Python、测试套件或测试监督器。

## 语义触发方式

Codex金手指不是在后台逐字监听聊天文本，也没有一份 Broker 侧的硬编码关键词白名单。Codex 是否主动采用它，主要由 Skill 的 `description` 进行语义匹配；插件显式开启隐式调用，并在描述中前置声明“为一个精确动作请求人类批准或拒绝”这一意图。

`同意`、`授权`、`批准`、`确认`、`允许`、`继续`、`拒绝`，以及 `Yes`、`Approve`、`Confirm`、`Authorize`、`Allow`、`Proceed`、`Reject`，都是提高召回率的示例而非完整词表。像“可以执行吗”“是否批准本次操作”“确认后继续”“May I proceed?”这样的表达，只要回答决定一个已明确动作能否继续，也属于同一授权意图。MCP 与 Broker 不要求这些固定词；`approved_reply` 可以是边界内配置的任意精确短回复。

为避免误触发，仅仅出现“确认”等字样并不够：收悉消息、核对事实（如“请确认版本号”）、偏好或设计选择、长期授权都不进入此流程。Codex 原生审批和本插件自身的安装、升级、修复、卸载仍按既有排除规则处理。

## 使用作用域与窗口生命周期

插件运行时与引用作用域是两层：`golden-finger` 应安装并启用于用户级 personal/global Codex 插件环境，使 Skill 和 MCP 在任何项目中都可被发现；`C:\finger` 这样的仓库目录只是开发源码，项目中的 `AGENTS.md` 也不会安装或复制插件。项目/全局标记只决定已全局可用的金手指何时被引用。

首次采用金手指时，Codex 必须先在普通对话中让用户约定引用范围：`仅本次`、`当前任务（推荐）`、`当前项目 <绝对根目录>`、`所有项目`，或暂不使用。作用域只是未来遇到合格请求时的路由偏好，不是长期授权；每一个动作仍需要一张被冻结的请求卡和一次窗口点击。若用户没有明确选择，不得擅自扩大范围。

`仅本次` 和 `当前任务` 只保留在当前任务语境中。`当前项目` 与 `所有项目` 分别在项目根或 Codex 用户目录的有效指令文件中持久化一小段带标记的作用域规则：该层已有 `AGENTS.override.md` 时写入它，否则使用 `AGENTS.md`，避免规则被 override 静默屏蔽。不复制整份 Skill；取消持久作用域时也只移除同一文件中的标记块。Broker 不保存作用域，因为它不能认证 Codex 的任务或项目身份，作用域也不会进入请求哈希、认领令牌或批准回执。

每个新请求提交前都先调用 `relay_health`。当窗口未运行、正在关闭或连接中断时，健康结果会失败关闭并给出两个结构化选择：`启动金手指窗口并继续作用域`，或 `取消金手指作用域`。Codex 不会自动启动独立授权窗口；它应引导用户双击桌面/开始菜单快捷方式，没有快捷方式时打开插件目录的 `scripts\launch_relay.pyw`，开发态则可在普通权限终端运行 `python scripts\relay_broker.py`。用户报告已打开后仍须重新检查健康状态。

中继和 MCP 都是拉取式的，不能在 Codex 回合结束后后台监测或主动唤醒。只有活跃回合里的健康检查、提交或轮询才能发现失联；仅当结果带有 `reason_code=relay_window_closed` 时才称为“窗口已关闭”，普通连接错误只称“窗口不可用”。重启窗口不会恢复旧的内存请求；取消作用域也不等于批准或拒绝当前动作，更不能撤销已经批准或运行中的命令。

## 一键启动

自 0.1.2 起提供用户主动触发、无控制台窗口的入口：

    scripts\launch_relay.pyw

源码/开发安装的桌面或开始菜单快捷方式应以当前用户的 `pythonw.exe` 为目标，以稳定源码目录的 `launch_relay.pyw` 为参数，并把工作目录设为该脚本所在的 `scripts` 目录。自包含发行包则直接指向稳定安装目录的 `bin\GoldenFinger.exe`，不要求 Python 或 PATH。两者都不得指向会随每次更新变化的 Codex 版本化缓存目录。

启动器不会自动启动、不会注册开机启动、不会请求管理员权限，也不会由 Codex 或 MCP 连接器调用。用户双击后，中继窗口可连续服务多个请求和 Codex 会话；只有窗口已关闭、异常退出或 Windows 重启后才需要再次双击。若启动失败或已有一个实例，错误会显示在对话框中，而不是消失在无控制台进程里。

创建桌面快捷方式属于一次单独的客户端变更，不由插件安装过程静默执行。

## 外观与新请求提醒

窗口优先读取 `~/.codex/config.toml` 的 `[desktop].appearanceTheme`，并兼容旧的根级字段；支持 `light`、`dark` 和 `system`。当值为 `system` 或配置不可读时，窗口跟随 Windows 应用主题；它不会注入或控制 Codex 进程。浅色、深色背景与强调色采用 Codex 外观设置公开的基线。在支持 Windows 亚克力背景的系统上，窗口背景保持 60% 不透明、文字保持 100% 不透明；透明客户区后方同时放置一个几乎不可见但 Alpha 非零的命中保护层，所以点击玻璃留白不会穿透到 Codex 或其他底层窗口。保护层若无法建立，界面会失败关闭透明客户区并退回不透明背景。窗口同时请求系统圆角和匹配的标题栏。当前 Windows `ACCENT_POLICY` 路径只提供背景着色 Alpha，不提供可调模糊半径；实际模糊范围由系统合成器决定。

窗口可调整尺寸，初始为 `980 × 720`，`920 × 600` 是舒适布局基线，同时允许 Windows Snap 缩到 `640 × 600`；若系统字体或 DPI 需要更大空间，运行时会继续上调高度。主体是“左右两条主操作通道 + 按需第三层”的渐进式三列：左侧合并显示 Codex 任务与中继请求，中间保留授权决定，详细参数默认收起，打开后在两列上方形成可滚动覆盖层，不再把窗口强行撑到屏幕外。宽度低于 820px 时会压缩任务列、隐藏可推导的等待策略文字，并把安全重启按钮移到独占行。居中的大圆形“同意本次”与两个小圆形“停止”“拒绝”会随可用空间重新计算位置和直径，最小命中尺寸和列表行高均为 40px；三者同时是原生 Windows Button，可向 UI Automation/Narrator 暴露名称、焦点、启用状态和 Invoke。筛选使用互斥单选状态，空清单、筛选无结果、任务清单不可用和本地中继状态分别显示。权限横幅已移除；命令详情仍明确显示普通用户或管理员权限，管理员模式还会注明获批命令继承该权限。

每次检测到新请求只提醒一次：列表自动按最新优先重排、自动选中最新项并滚入视野；若窗口已最小化则恢复，并在仍有待确认请求期间保持置顶。新请求只触发一次 Windows 前台激活尝试，键盘焦点落在非操作性的请求列表，不会把 Enter 或空格预设为批准；250 ms 刷新也不会再清除正在按下的按钮状态。最后一个待确认请求处理后会自动取消置顶。

“新请求提示音”默认开启，可在窗口右上角随时关闭或重新开启。选择只保存到中继自己的 `ui-settings.json`，不会修改 Codex 或 Windows 设置；重复轮询同一请求不会再次发声。

右上角“诊断”会打开可滚动、可复制的只读安装快照：Broker/连接器版本与精确 build ID、协议号、源码或自包含运行模式、权限、Job Object 能力、插件启用状态、版本化缓存、快捷方式及最近连接器指纹。快照明确脱敏，不包含端点 bearer secret、`claim_token`、原始连接器实例 ID、请求正文或命令输出。它不调用或控制 Codex，也不会自动修复、安装或切换版本。

## 轮询与执行设置

窗口固定显示 `等待 900 秒 × 10 次`。它派生出 `9000 秒`（2 小时 30 分）的待确认总预算和同样长的命令执行上限，不再保存轮询秒数或次数输入；旧版 `ui-settings.json` 中的这两个字段会被忽略，只有提示音偏好继续持久化。

每个请求都会冻结并哈希固定策略、单次等待、轮询上限和派生命令超时。Codex 的每个活动响应都会收到下一次精确参数、已用次数和剩余次数，不保存或猜测另一套值。正数等待只在请求仍为 `pending` 时消耗次数；次数或时间预算用尽仍无人决定时，请求进入 `expired`。命令进入 `running` 后改由已经冻结的执行超时负责，不能因为确认阶段的计数用完而被静默遗留或终止。

这组同步字段、窗口停止语义、来源证据与请求认领使用本地协议版本 5。端点读取和每次认证请求都会同时比对包版本与运行时 build ID；只要窗口、MCP 连接器或缓存来自不同构建就失败关闭。发布安装时窗口运行时和 Codex 客户端插件必须配套升级。

## 开发态启动

安装插件前，用户需要在普通权限终端中手动启动窗口：

    python scripts\relay_broker.py

本仓库没有自动安装、自动启动或 Codex 配置修改。插件安装、创建快捷方式和首次实际联调是彼此独立的授权步骤。

## 自包含 Windows 发行包

`requirements-build.txt` 只列构建期依赖。下面的构建会在 `build/` 中盖入同一 `rel-…` build ID，用 PyInstaller 的共享 `COLLECT` onedir 生成无控制台窗口 `GoldenFinger.exe` 和控制台 MCP 连接器 `golden-finger-mcp.exe`，并让二者共用同级 `golden-finger.runtime` 目录，再把插件、SHA-256 清单和 `BUILD-ID.txt` 打包到 `dist/`；两个 EXE 的既有 `bin\...` 路径不变。它不会安装插件、修改 Codex 配置或创建快捷方式。

    python -m pip install -r requirements-build.txt
    python scripts\build_windows_release.py
    python scripts\verify_windows_release.py dist\golden-finger-0.2.0

验证器逐文件复算清单，检查共享 onedir runtime 目录，实际启动 MCP EXE 完成 `initialize`，并让窗口 EXE 用 `--self-test-output` 在不打开 GUI 的情况下验证版本、build ID、自包含模式和 Windows Job Object。运行、复制或安装时必须保留完整发行包，不能只取两个 EXE。GitHub Actions 的 Windows runner 会从干净检出重复单元测试、静态校验、构建和验证；本地成功不替代真实干净 Windows 机器的首次启动与交互验收。

## 使用方式

1. 首次采用时，用户在普通对话中选择金手指的路由作用域。
2. Codex 调用 `relay_health`；若窗口不可用，用户选择启动并保留作用域，或取消作用域。
3. 窗口健康后，Codex 调用 \`request_consent\` 或 \`request_command_execution\`，同时提交真实的来源标签、项目根和任务标题；Broker 返回请求 ID 与仅当前工具链持有的认领令牌。
4. 用户核对来源项目/任务/连接器指纹、动作、目标、风险、恢复路径、命令、脚本摘要、请求哈希和认领指纹。
5. 用户点击“同意本次”或“拒绝”；若只想结束等待而不表达两者，点击“停止”。
6. MCP 工具把结构化结果返回当前 Codex 工具调用；若仍为 \`pending/running\`，Codex 在当前回合按返回的精确参数重复等待已认领请求，直到完成、拒绝、失败或过期，再据此继续或停止。

## 开发验证

在 Codex 内只做无副作用的语法、清单和 Skill 静态验证。涉及启动窗口、执行命令或实际连接 Codex 的测试，应在外部终端中按单独授权进行。

静态验证入口：

    python scripts\static_validate.py

外部单元测试入口：

    python -m unittest discover -s tests -v

外部窗口联调步骤见 [EXTERNAL-TESTING.md](EXTERNAL-TESTING.md)。附带的 \`manual_smoke_client.py\` 只有固定“同意”与固定打印两种场景，不提供任意命令入口，也没有批准接口。

## 版本状态

0.2.0 把跨项目隔离从“知道请求 ID 即可读取”升级为每请求能力式认领：请求 ID 只负责定位，随机 `claim_token` 才允许读取、等待或取消；连接实例随机 ID 同时隔离幂等键命名空间。窗口新增项目/任务/来源标签与连接器指纹供人工辨认，但明确保持弱绑定。端点和认证请求严格比对组件版本与 build ID；命令冻结可执行文件及直接脚本参数，启动前复验，并在 Windows Job Object 中约束进程树。窗口采用默认收起详情的三列极简布局，并增加只读任务清单与失败关闭的安全重启门禁；任务标题只作不受信任的显示文本，重启能力不进入授权传输。窗口同时提供脱敏安装诊断和明确的关窗后果，自包含 Windows 构建产出 Broker/MCP EXE、哈希清单与干净 Windows CI 验证。当前源码把等待固定为 `900 × 10`，并增加不会表达同意或拒绝、可立即唤醒等待的窗口“停止”操作；MCP 的 `notifications/cancelled` 仍是同步连接器上的尽力取消。Skill 仍按单次授权意图匹配，首次采用时协商路由作用域，窗口失联时提供启动或取消作用域。本版请求前缀为 `gfr_`，本地协议为 5，因此窗口运行时与客户端插件必须来自同一构建。

0.1.9 将窗口改为极简响应式布局：加入 DPI 感知的 `920 × 600` 基线最小尺寸，固定底部操作栏和右下角“同意本次”，把等待策略收敛为实时乘法公式，并移除重复的权限横幅。命令详情继续明确显示执行权限及管理员继承影响；授权、轮询、透明防穿透和本地协议边界不变。

0.1.8 将品牌统一为“Codex金手指 / Golden Finger for Codex”，同时保留“人机授权中继”和“Yes工程师”作为功能与搜索关键词。内部插件 ID、Skill ID 与源码目录统一为 `golden-finger`，MCP 配置键使用 `golden_finger`；这是需要重新发布和安装的不兼容标识迁移，本地协议版本仍保持 2。

0.1.7 为玻璃客户区加入非零 Alpha 命中保护层，杜绝点击穿透；同时把等待设置重排为两个输入和一个实时派生结果，取消保存按钮，将单次轮询下限提高到 10 秒，并让命令执行上限自动等于轮询秒数与轮询次数的乘积。它继续保持背景 60%、文字 100%，允许 `request_consent` 为后续 Codex 管理操作收集一次性自然语言授权，并禁止中继器直接启动或控制 Codex。它仍是源码原型，不是普通用户发行包。后续发行目标是单文件 Windows 窗口程序，不要求管理员权限、Python、PATH 或手动依赖安装。
